## Шаг 1. Фундамент адаптивности

Общая инфраструктура, на которую опираются все следующие шаги. Сам по себе внешний вид почти не меняет.

### 1.1. Хук определения мобильного режима

- Создать `src/hooks/useIsMobile.ts` на `window.matchMedia("(max-width: 767px)")`.
- Подписка на изменение (поворот экрана, ресайз окна), корректная отписка.
- Порог 768px — совпадает с брейкпоинтом `md` в Tailwind, чтобы CSS и JS не разъезжались.

### 1.2. Состояние мобильной навигации в store

- Добавить в `store.ts`: `isFolderPanelOpen`, `isSidebarOpen` (обе по умолчанию `false`) и действия `toggleFolderPanel`, `toggleSidebar`, `closeMobilePanels`.
- Не сохранять в localStorage: при новом заходе панели должны быть закрыты.

### 1.3. Высота экрана и безопасные зоны

- Заменить `h-screen` на `h-dvh` в `App.tsx`: `100vh` на мобильных браузерах считается **без учёта адресной строки**, из-за чего низ интерфейса уезжает под неё.
- Добавить `env(safe-area-inset-*)` для айфонов с «чёлкой» и жестовой полосой.
- Запретить горизонтальную прокрутку body.

**Коммит:** `feat: инфраструктура адаптивности (хук useIsMobile, состояние панелей, dvh)`

## Шаг 2. FolderPanel — скрываемая панель (главный приоритет)

### 2.1. Превратить в выдвижную панель (off-canvas drawer)

- На экранах ≥768px — всё как сейчас: колонка 260px в потоке.
- На экранах <768px — `position: fixed`, выезжает слева поверх контента, полупрозрачный оверлей сзади.
- Анимация через `transform: translateX()` (не `width`) — она идёт на GPU и не дёргается на слабых телефонах.
- Ширина на мобильном: `min(85vw, 320px)` — чтобы край контента оставался виден и было понятно, куда нажать для закрытия.

### 2.2. Кнопка вызова панели

- Кнопка-гамбургер в шапке контентной области, видна только на мобильном.
- Рядом — название текущей категории, чтобы человек понимал, где находится.

### 2.3. Автозакрытие

- При выборе файла панель закрывается сама (иначе выбранное не видно за ней).
- Закрытие по клику на оверлей и по кнопке «крестик» в шапке панели.
- Блокировка прокрутки фона, пока панель открыта.

### 2.4. Клавиатура и жесты

- `Esc` — закрыть.
- Свайп влево по панели — закрыть (реализовать на pointer events, без сторонних библиотек).
- Фокус при открытии переходит внутрь панели, при закрытии — возвращается на кнопку (доступность).

### 2.5. Пустое состояние «Select a category»

- Сейчас при отсутствии выбранной категории `FolderPanel.tsx:608-624` рисует заглушку-колонку на 260px. На мобильном она бессмысленна.
- На мобильном: не показывать колонку вообще, а открыть панель категорий.

**Коммит:** `feat: FolderPanel скрывается в мобильном виде (off-canvas drawer)`

## Шаг 4. Тач-цели и скрытые действия

### 4.1. Размер целей нажатия

- Минимум 44×44px для всех кнопок (рекомендация Apple HIG и Material Design).
- Проверить мелкие иконки в `FolderPanel`, `Sidebar`, `LinksView` — сейчас там есть `text-[10px]` и иконки 14–16px.

### 4.2. Действия, скрытые под наведением

- `group-hover:opacity-100` в 10 компонентах: на тач-устройствах наведения не существует, кнопки недостижимы.
- Решение: на устройствах без hover (`@media (hover: none)`) показывать действия всегда либо прятать их в меню «⋯», которое открывается по нажатию.

### 4.3. Контекстные меню

- Правый клик на телефоне не воспроизвести. Добавить долгое нажатие (long-press, ~500 мс) как альтернативу — или кнопку «⋯» из пункта 4.2, что надёжнее и понятнее.

**Коммит:** `fix: тач-цели и доступность действий без наведения`

## Шаг 5. Drag-and-drop на тач-экранах

Сейчас перетаскивание построено на HTML5 DnD (`draggable`, `onDragStart`) — этот API **не работает на тач-экранах в принципе**, палец ничего не перетащит. Затронуты `FolderPanel`, `LinksView`, `Sidebar`.

### 5.1. Выбрать подход (обсудим отдельно)

- **Кнопки «вверх/вниз»** в меню элемента — просто, надёжно, работает везде. Порядок меняется по одному шагу.
- **Режим сортировки** — отдельная кнопка «Изменить порядок», элементы получают ручки для перетаскивания на pointer events. Ближе к текущему поведению, но заметно больше кода.
- **Библиотека `@dnd-kit`** — полноценный DnD с поддержкой тача. Красиво, но это +1 зависимость и переписывание всех трёх мест.

### 5.2. Реализовать выбранное

**Коммит:** `feat: изменение порядка элементов на тач-устройствах`

## Шаг 6. Контентные виды

Каждый подшаг самостоятелен, порядок можно менять.

### 6.1. `LinksView` (1856 строк, самый большой)

- Сетка карточек: сейчас `sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4` — проверить, что на 360px одна колонка не ломается.
- Панель фильтров/поиска: свернуть в одну строку с иконкой.

### 6.2. `PromptsView` и `CommandsView` — таблицы

- Есть колонки, скрытые через `md:table-cell` / `lg:table-cell` — то есть на мобильном таблица уже урезается.
- Таблицу на узком экране лучше превратить в список карточек: горизонтальная прокрутка таблиц — плохой мобильный опыт.

### 6.3. `PlaybookView` и `ContextPanel`

- Боковая панель контекста на мобильном — в нижнюю шторку (bottom sheet) или вкладку.

### 6.4. `NoteEditor`

- Панель инструментов должна переноситься по строкам, а не обрезаться.
- Проверить, что редактор не перекрывается экранной клавиатурой.

**Коммит:** отдельный на каждый подшаг

## Шаг 9. Проверка результата

### 9.1. Эмуляция в браузере

- DevTools → Device Toolbar. Контрольные ширины: **360px** (Android), **390px** (iPhone), **414px** (крупные), **768px** (граница планшета).

### 9.2. Проверка на реальном телефоне

- Важный нюанс: сейчас в `vite.config.ts` стоит `server.host = "127.0.0.1"` — с телефона по сети такой сервер **не виден**. Для проверки нужно временно запустить `npm run dev -- --host 0.0.0.0` и открыть на телефоне адрес вида `http://<IP-компьютера>:5173`.
- Проверить, что компьютер и телефон в одной сети и firewall не блокирует порт.

### 9.3. Чек-лист живых сценариев

- Выбрать категорию → выбрать файл → отредактировать → вернуться назад.
- Переименовать и удалить элемент (без наведения мышью).
- Изменить порядок элементов.
- Открыть настройки, импорт/экспорт.
- Повернуть телефон в альбомную ориентацию.
