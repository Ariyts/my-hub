Дата составления: 2026-07-14 · Обновлён: 2026-07-15
Приложение: Knowledge Hub (React 19 + Vite 7 + Tailwind 4 + Zustand 5)

## Цель

Сделать приложение более функциональным и визуально целостным, **не ломая текущий
функционал**. Работа разбита на **Задачи по вкладкам Categories**:

| Задача | Что охватывает |
| --- | --- |
| **Задача 0. Фундамент** | Дизайн-система, общая оболочка представлений (референсы со скринов), общие компоненты, производительность |
| **Задача 1. Notes** | Структура заметок, оглавление, изображения, тулбар, подсветка кода, wiki-связи |
| **Задача 2. Links** | Мульти-раскладки (Tiles/Grid/List/Board/Compact) как на референсах, теги, мультивыбор, надёжные метаданные, импорт закладок |
| **Задача 3. Playbook** | DnD секций/команд, устранение setTimeout-хаков, синхронизация чеклиста, подстановка переменных, фазы, шаблоны, экспорт секции |

> Commands и Prompts в этот план детально не входят (по вашему решению), но
> **автоматически получают** дизайн-токены и общую оболочку из Задачи 0. Их
> доводку можно вынести в отдельную задачу позже.

## Диагностика (кратко, зачем нужен Фундамент)

| Находка | Последствие |
| --- | --- |
| Нет дизайн-токенов; ~754 захардкоженных hex, тема через тернарники `isDarkTheme ? "#..." : "#..."` | цвет/тему нельзя менять централизованно; любой рестайл = ручная правка сотен мест |
| UI-паттерны (секции, inline-add, copy, палитры, карточки) переписаны в каждом виде | правка дизайна в одном месте не тиражируется |
| Нет единой «оболочки представления» (тулбар, сортировка, раскладки) | каждый вид выглядит по-своему, референс со скринов негде переиспользовать |
| Нет виртуализации, есть O(n²) в LinksView, отладочные `console.log` | тормоза и шум при росте данных |

Что уже хорошо и **трогать не будем**: мобильная адаптация, Zustand+persist,
корзина с soft-delete, GitHub-синхронизация одним коммитом.

### Шаг 0.C.1. `ViewToolbar` — верхняя панель

- Счётчик «N / N items».
- Переключатель раскладок: **Tiles · Grid · List · Board · Compact**.

### Шаг 0.C.2. `ViewHeader` — шапка коллекции
- Строка-«хлебная крошка» (`~/ RESOURCES`), крупный заголовок + подпись + иконка,

### Шаг 0.C.4. Пять раскладок (`LayoutSwitch`)

# Задача 1. Notes

Сейчас Notes — самая «бедная» категория: одно текстовое поле с Markdown, без
структуры внутри заметки. Подтягиваем до уровня Playbooks/Links.

### Шаг 1.1. Оглавление (TOC) с автогенерацией
- Парсить `##`/`###` и показывать кликабельное TOC сбоку/сверху.
- Зачем: длинные заметки (AD, Linux, Windows) без навигации по заголовкам неудобны.

### Шаг 1.2. Расширенный тулбар редактора
- Добавить: **Таблица**, **блок кода с выбором языка**, **зачёркивание**,
  **разделитель**, **чекбокс `- [ ]`**. (Сейчас: H1/H2/Bold/Italic/Code/Link/List/Quote.)
- Привязать хоткеи Ctrl+B/I/K; добавить счётчик слов/символов.

### Шаг 1.3. Синтаксическая подсветка в блоках кода
- Подключить `highlight.js` (уже в зависимостях) в превью и, по возможности, в
  редактируемой области. Зачем: заметки по Linux/SSH/DNS без подсветки читаются плохо.

### Шаг 1.4. Вставка изображений
- Drag-and-drop, paste из буфера, upload. Хранение — согласовать (base64 в
  контенте / IndexedDB / GitHub-ассеты). Зачем: скриншоты и диаграммы для инфобеза.

### Шаг 1.5. Вложенные заметки (подстраницы)
- Wiki-подобная структура: главная заметка → подстраницы (модель: заметка может

### Шаг 1.6. Wiki-связи и backlinks
- Синтаксис `[[Название заметки]]` с автоподстановкой, кликабельным переходом и
  панелью обратных ссылок. Зачем: Kerberos → AD → DNS связаны.

**Порядок:** 1.1 → 1.2 → 1.3 (низкий риск, быстрый эффект), затем 1.4 → 1.5 → 1.6

## Порядок задач и логика

1. **Задача 0 (Фундамент) — первой и обязательно.** Токены + оболочка + общие
   компоненты; на них опирается всё остальное. Внутри неё: 0.A → 0.B → 0.C → 0.D → 0.E.
2. **Задача 2 (Links)** — флагман новой оболочки (у вас уже есть прототип-референс),
   быстрый видимый результат.
3. **Задача 1 (Notes)** — наибольший прирост функциональности «с нуля».
4. **Задача 3 (Playbook)** — доводка самой зрелой категории.

Порядок 2/1/3 после Фундамента можно переставлять по вашему приоритету — они
независимы, поскольку опираются на общую Задачу 0.
