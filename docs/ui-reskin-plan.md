# План визуального редизайна (skin) — «pro-tool»

Дата составления: 2026-07-30
Приложение: Knowledge Hub (React 19 + Vite 7 + Tailwind 4 + Zustand 5)

## Что решили

- **Глубина:** только визуал (skin). Структура экранов, навигация, модель данных,
  store и вся логика — **не меняются**. Меняем цвет, типографику, плотность,
  скругления, границы, тени, иконки, состояния.
- **Направление:** плотный «pro-tool» — тёмная тема по умолчанию, компактно,
  информационно-плотно, чёткие акценты по типам контента. Ориентир по духу —
  Raycast / IDE / GitHub-dark, без консюмерской «мягкости».
- **Референс:** на усмотрение исполнителя (best practices).

## Ключевой факт, определяющий стратегию

Дизайн-токены уже введены ([index.css](../src/index.css),
[design-system.md](design-system.md)), но миграция компонентов на них осталась
пилотной. По факту в `src/` сейчас:

- **~472 захардкоженных hex** в 22 файлах;
- **~97 тернарников `isDarkTheme ? "#..." : "#..."`** в 8 файлах.

Больше всего «сырого» цвета — ровно в самых заметных поверхностях:
`Sidebar` (43 hex + 27 тернарников), `FolderPanel` (31 + 26), `LinksView` (93),
`PromptsView` (85 + 13), `CommandsView` (57 + 6), `NoteEditor` (16 + 8),
`SettingsModal` (44 + 10).

**Вывод:** просто поменять значения токенов — мало. Новый скин применится только
там, где цвет уже идёт через токены. Значит, редизайн = два параллельных трека:

- **Трек A. Токены** — задать новую палитру/плотность (глобальный эффект на уже
  мигрированных участках, мгновенно).
- **Трек B. Домиграция** — перевести захардкоженный цвет в видимых поверхностях
  на токены, чтобы скин реально «прорастал» везде.

Оба трека — строго визуальные. Ни модель данных, ни store, ни обработчики не
затрагиваются.

## Целевой облик «pro-tool» (спецификация)

Ниже — предлагаемые ориентиры. Точные значения дошлифуем в Фазе 1 на реальном
экране; здесь фиксируем направление.

### Палитра — тёмная тема (основная)

Глубже и нейтральнее текущей slate, с внятной иерархией «холст → панель →
утопление» и **видимой** границей (сейчас `--border` совпадает с `--bg-elevated`
и почти не читается).

| Токен | Сейчас (dark) | Предложение | Роль |
| --- | --- | --- | --- |
| `--bg` | `#0f172a` | `#0b0e14` | холст, глубокий near-black с холодным подтоном |
| `--bg-elevated` | `#1e293b` | `#12161f` | панели, карточки |
| `--bg-sunken` | `#334155` | `#1a1f2b` | поля ввода, hover-лунки |
| `--border` | `#1e293b` | `#232a38` | **видимый** hairline (ключ к «pro-tool») |
| `--border-subtle` | `#334155` | `#1a1f2b` | мягкий разделитель |
| `--text` | `#e2e8f0` | `#e6e9ef` | основной |
| `--text-muted` | `#94a3b8` | `#9aa4b2` | вторичный |
| `--text-subtle` | `#64748b` | `#6b7280` | подписи |

### Акценты по типам (единый, чуть приглушённый набор в духе GitHub-dark)

Сейчас — Material-500 (немного «громкие»). Предложение — когезивный набор,
одинаково читаемый на тёмном холсте и на светлом:

| --- | --- | --- |
| Notes | `#4caf50` | `#3fb950` |
| Commands | `#2196f3` | `#58a6ff` |
| Links | `#ff9800` | `#f0883e` |

Состояния (`--danger/success/warning/focus-ring`) — подстроим под новую палитру
на том же шаге.

### Плотность, типографика, форма

«Pro-tool» = компактный ритм и сдержанная форма. Т.к. радиусы/тени/кегль в проекте
живут на встроенной шкале Tailwind (переопределять их в `:root` **нельзя** — это
меняет утилиты глобально), плотность задаём **через классы при домиграции каждой
поверхности**, а не через токены:

- **Скругления:** крупные `rounded-2xl` → `rounded-lg`/`rounded-md`; иконочные
  контейнеры `rounded-2xl` → `rounded-lg`.
- **Плотность строк:** списки/строки `py-3` → `py-1.5…py-2`; уплотнить `gap-*`.
- **Границы вместо теней:** «pro-tool» опирается на hairline-границы, а не на
  мягкие тени — тени приглушаем (`shadow-sm`/без тени).
- **Базовый кегль:** дать опцию 13px (сейчас `--app-font-size: 14px`) — уже
  управляется `settings.fontSize`, добавим более плотный дефолт.
- **Моно-акценты:** URL/команды/переменные — на `font-code`, чтобы «читалось как
  инструмент».

Эти изменения вносим **вместе с домиграцией** конкретной поверхности (Трек B),
чтобы не трогать компонент дважды.

## Фазы и шаги

Порядок — по убыванию заметности и по возрастанию площади правок. После **каждого
шага** — остановка и текст возможного коммита (правило CLAUDE.md). Новый шаг — только
после разрешения.

### Фаза 1. Токены нового скина (Трек A) — фундамент облика

**Шаг 1.1. Новая палитра в `index.css`.**
Переопределить значения `--bg*`, `--border*`, `--text*`, акценты, состояния для
`:root` и `:root[data-theme="dark"]`. Ничего, кроме значений, не трогаем — имена
токенов и мост в Tailwind остаются. Эффект: во всех уже-мигрированных местах скин
меняется мгновенно.
*Коммит:* `feat(design): pro-tool color palette (light/dark)`

**Шаг 1.2. Обновить `design-system.md`.**
Синхронизировать таблицу значений и добавить раздел «Плотность/форма pro-tool»
(правила скруглений, границ, теней, кегля) как чек-лист для домиграции.
*Коммит:* `docs(design): document pro-tool palette & density`

> После Фазы 1 сделаем визуальную сверку: где скин «пророс», а где остался старый
> цвет (это и есть карта работ Трека B).

### Фаза 2. Оболочка (Трек B) — максимальная заметность

Каркас виден на каждом экране, поэтому идёт первым.

**Шаг 2.1. `Sidebar`** — перевести hex/тернарники на токены, уплотнить, hairline.
*Коммит:* `refactor(sidebar): migrate to tokens + pro-tool density`

**Шаг 2.2. `FolderPanel`** — то же (папки/файлы, состояния выбора/hover).
*Коммит:* `refactor(folder-panel): migrate to tokens + pro-tool density`

**Шаг 2.3. `MobileTopBar` + плейсхолдеры «No … selected» в `App.tsx`** —
дочистить остатки (`hover:bg-slate-*`, иконочные контейнеры) под новый скин.
*Коммит:* `refactor(shell): pro-tool skin for topbar & placeholders`

### Фаза 3. Контентные представления (Трек B) — основная площадь

По одному виду за шаг, каждый — самостоятельный, проверяемый.

**Шаг 3.1. `LinksView`** (самый «сырой», 93 hex) — карточки/раскладки/секции на
токены, компактнее, границы вместо теней.
*Коммит:* `refactor(links): migrate to tokens + pro-tool density`

**Шаг 3.2. `PlaybookView` и `components/playbook/*`** — карточки команд, фазы,
context-панель, hero; свести акценты фаз на токены.
*Коммит:* `refactor(playbook): pro-tool skin`

**Шаг 3.3. `PromptsView`** (85 hex) — таблица/карточки/секции.
*Коммит:* `refactor(prompts): migrate to tokens + pro-tool density`

**Шаг 3.4. `CommandsView`** (57 hex).
*Коммит:* `refactor(commands): migrate to tokens + pro-tool density`

**Шаг 3.5. `NoteEditor`** — редактор/превью/тулбар (подсветка кода уже на токенах).
*Коммит:* `refactor(notes): pro-tool skin for editor & preview`

### Фаза 4. Модалки и вспомогательное (Трек B)

**Шаг 4.1. `SettingsModal`** (44 hex + 10 тернарников).
**Шаг 4.2. `TrashModal`, `CommandPalette`, `ImportExport*`, `WorkspaceSwitcher`,
`UndoToast`.**
*Коммиты:* по одному на модалку: `refactor(<modal>): pro-tool skin`.

### Фаза 5. Финальная полировка

**Шаг 5.1. Микросостояния** — focus-ring, hover, active, drag-индикаторы,
скроллбары (`.dark-scrollbar`, `.drop-target-active` — сейчас с хардкодом `#ff9800`).
**Шаг 5.2. Сквозная сверка** обеих тем на всех экранах; вычистить оставшиеся
единичные hex (`grep`-проверка → 0 в UI-компонентах).
*Коммиты:* `polish(design): unify interactive states`, `chore(design): kill residual hex`.

## Гарантия «не сломать функционал»

1. **Только визуальный слой.** Меняем значения токенов и classNames/inline-стили
   цвета; JSX-структуру, пропсы, обработчики, store и типы — нет.
2. **Один узел за раз.** Каждый шаг — один компонент/файл, отдельный коммит,
   отдельная проверка. Откат тривиален.
3. **Токен-своп эквивалентен.** Замена `isDarkTheme ? "#a" : "#b"` на токен —
   поведенчески нейтральна: токен и есть эти же значения через `data-theme`.
4. **Проверка на каждом шаге:** `npm run typecheck` + `npm run build` + визуальный
   прогон изменённого экрана в обеих темах (и на мобильной ширине).

## Оценка объёма

| Фаза | Файлов | Заметность | Риск |
| --- | --- | --- | --- |
| 1. Токены | 2 | глобальная | очень низкий |
| 2. Оболочка | 3 | максимальная | низкий |
| 3. Представления | ~9 | высокая | низкий |
| 4. Модалки | ~6 | средняя | низкий |
| 5. Полировка | точечно | средняя | низкий |

## Что НЕ входит

- Изменения навигации/раскладки экранов, модели данных, store — вне skin-редизайна
  (это был бы вариант «визуал + оболочка» / «полный редизайн»).
- Функциональные доработки категорий — они уже описаны в
  [design-improvement-plan.md](design-improvement-plan.md) и здесь не дублируются.

## Рекомендуемый старт

Начать с **Фазы 1, Шаг 1.1** (новая палитра в токенах) — один файл, глобальный
видимый эффект, тривиальный откат. После него сделаем сверку и пойдём по оболочке.

Жду твоего разрешения на старт и подтверждения:
1. согласны ли предложенные значения палитры (или скорректировать);
2. ок ли порядок фаз (оболочка → представления → модалки).
